# Money Tracker implementation plan

The implementation follows the 16 November 2026 audit and the supplied implementation brief. Historical reports remain unchanged. Financial rules, server authorization, existing routes, BDT/Asia Dhaka policy, and persisted schema remain the product boundaries.

1. Refresh the dependency evidence, upgrade compatible affected packages, and verify the dependency stage separately. Capture the existing UI with synthetic fixtures before visual changes.
2. Repair dashboard snapshot ownership and pagination generations, then absolute session expiry and the shared OAuth start boundary. Add regressions with each change.
3. Replace the quarantine overlay, bound readiness database resources, preserve early transaction years, repair the canonical browser fixture, and format supported aggregate cents exactly.
4. Apply a shared, restrained light visual system to existing sign-in, dashboard, groups and administration screens; improve responsive navigation, forms and shared recovery states. Preserve the unresolved ownership/offboarding policy.
5. Qualify on a newly provisioned disposable PostgreSQL 17 cluster with the pinned toolchain. Run both bundlers and Proxy/runtime checks, canonical and managed production browser workflows, focused races/security regressions, and viewport/zoom checks. Record screenshots and a finding-by-finding results matrix with any external verification still outstanding.

Dependency changes are limited to package manifests and lockfile until that stage is validated. Application fixes and visual changes follow as distinct file groups; final verification assesses their combined behavior. No production secrets or application database are used.
